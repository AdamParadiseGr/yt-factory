# n8n: управление конвейером

n8n здесь управляет, а видео собирает GitHub Actions. Пять workflow в `workflows/`:

| Файл | Что делает |
|---|---|
| `1-approval.json` | Кнопки под роликом в Telegram: Одобрить (копия в Google Drive), Переделать (новая сборка), Другой заголовок (3 варианта), Отклонить, Опубликовано. Команды `/pause kids` и `/resume kids` |
| `2-scheduler.json` | Раз в час читает таблицу-панель и запускает `produce` для каналов, у которых сейчас время. Заменяет cron |
| `3-llm-rotator.json` | Ротатор ключей Gemini, Groq и OpenRouter со счётчиками и паузой при исчерпании лимита. Ежедневный отчёт по лимитам в 06:00 UTC |
| `4-publish-queue.json` | В часы публикации из панели присылает готовый к загрузке пакет: заголовок, описание, теги, ссылку на Drive, настройку аудитории |
| `5-backup.json` | Раз в сутки копирует все workflow в `n8n/backup/workflows.json` в репозитории |

Если n8n недоступен, конвейер не встаёт целиком: запросы к моделям уходят напрямую по ключам,
а `produce` можно запустить вручную в GitHub (Actions → produce → Run workflow). Без n8n не
работают расписание, кнопки, напоминания и счётчик лимитов.

## 1. Хостинг

Выберите одно (файлы для обоих лежат здесь):

- **Виртуальная машина (Oracle Always Free и т.п.):** `docker-compose.yml` + `.env.example`.
  Нужен адрес вида `имя.duckdns.org` на эту машину; HTTPS получит Caddy. В правилах сети Oracle
  откройте порты 80 и 443. Команда: `cp .env.example .env`, заполнить, `docker compose up -d`.
- **Render free:** `render.yaml`. Сервис засыпает через 15 минут, поэтому нужен внешний пинг
  `https://<сервис>.onrender.com/healthz` каждые 5 минут (UptimeRobot или cron-job.org; проверьте,
  что условия бесплатного тарифа пинга вам подходят), а база должна быть внешней (Neon или
  Supabase): иначе после перезапуска пропадут workflow и учётные данные. Не пропускайте
  ежедневный бэкап (workflow 5).

В окружении n8n должны быть `N8N_BLOCK_ENV_ACCESS_IN_NODE=false`, `N8N_LLM_TOKEN`,
`GEMINI_API_KEYS`, `GROQ_API_KEYS`, `OPENROUTER_API_KEYS` (можно пустым), `TELEGRAM_BOT_TOKEN`.
Они уже прописаны в compose и в blueprint, значения берутся из `.env` или панели Render.

## 2. Таблица-панель (Google Sheets)

1. Создайте таблицу, импортируйте `control-panel.csv`, назовите лист **panel**.
2. Столбцы: `channel`, `enabled` (TRUE/FALSE, это пауза), `produce_hour_utc`, `videos_per_run`,
   `days` (дни через запятую), `genres` (необязательно: жанры на этот запуск через `|`; пусто означает
   взять из конфига канала), `publish_hour_utc` (час напоминания о публикации), `videos_per_day`.
3. Ориентир по часу публикации: вечер в США, около 23:00 UTC летом (скорректируйте по отчёту
   `besttime` через несколько недель).

## 3. Подключение

1. Заполните плейсхолдеры одной командой (или найдите и замените вручную):
   `python3 n8n/configure.py ВАШ_ЛОГИН/yt-factory ВАШ_TELEGRAM_CHAT_ID ID_ТАБЛИЦЫ ID_ПАПКИ_DRIVE`
   Можно прислать мне эти четыре значения (они не секретные), и я подготовлю файлы.
2. Импортируйте все пять файлов (Workflows → Import from file).
3. Создайте credentials и привяжите к узлам:
   - **Telegram yt-factory** (Telegram API): токен бота;
   - **GitHub PAT** (Header Auth): имя `Authorization`, значение `Bearer <токен>`. Токен fine-grained,
     только этот репозиторий, права Contents и Actions: Read and write;
   - **Gemini key** (Header Auth): имя `x-goog-api-key`, значение ключ Gemini;
   - **Google Sheets** и **Google Drive** (OAuth2): создаются в n8n через учётную запись Google.
     Нужен OAuth client в вашем проекте Google Cloud (тот же проект, где будете включать YouTube API);
   - **n8n API** (для бэкапа): Settings → n8n API → создать ключ.
4. Включите (Active) все пять workflow.
5. В GitHub добавьте секреты `N8N_LLM_URL` (production-адрес вебхука workflow 3:
   `https://<ваш-хост>/webhook/yt-llm`) и `N8N_LLM_TOKEN` (то же значение, что в окружении n8n), а
   также переменную Actions `APPROVAL_BUTTONS` = `1`.
6. Проверка: в панели поставьте текущий час UTC в `produce_hour_utc` и подождите до начала следующего
   часа. В Telegram придёт «Запущена сборка».

Telegram разрешает у бота только один способ получения обновлений: другой webhook у этого бота
должен быть удалён. Telegram Trigger регистрируется по `WEBHOOK_URL` (HTTPS обязателен).

## Что не проверено

Workflow сформированы по документации n8n; проверена структура (узлы и связи) и синтаксис
JavaScript во всех Code-узлах. В живой n8n они не импортировались и не запускались. Больше всего
риска в параметрах узлов Google Sheets, Google Drive и Telegram (названия полей зависят от версии)
и в том, что n8n по умолчанию закрывает доступ к переменным окружения из Code-узлов (мы это
отключаем в окружении). Если импорт или запуск даёт ошибку, пришлите её текст.

Ограничения: Telegram позволяет боту скачать файл не более 20 МБ, для больших роликов копия в
Drive не сохранится (это показано в ответе на кнопку), ролик остаётся в Telegram и в артефактах
запуска. Счётчики ротатора хранятся в самом n8n и сбрасываются в 00:00 UTC или при потере базы.
